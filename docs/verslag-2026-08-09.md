# Sessieverslag 9–10 augustus 2026 — van leeg mapje naar live systeem

## Kernresultaat

In twee dagen is het project van een lege map gegroeid naar een draaiend systeem:
een **live vertragingskaart** van het treinverkeer in NL/BE/FR/CH (DE volgt), op
echte spoorgeometrie, gevoed door een aggregator die tegelijk **historische
punctualiteitsdata verzamelt** voor de latere reisplanner. De hele pijplijn draait
op gratis diensten (GitHub Actions, Cloudflare R2, Google Cloud e2-micro) en alle
kernaannames voor de app (fase 1) zijn met metingen gevalideerd.

## 1. Planvorming en bronnenonderzoek (dag 1)

- **CLAUDE.md** en **PLAN.md** opgezet: projectvisie (Planmodus + Reismodus, vijf
  landen, rijke constraints), architectuur, fasering.
- Kernbeslissingen: **Kotlin/Compose** voor de app; **eigen RAPTOR-engine op
  GTFS-data** (geen enkele externe planner-API ondersteunt de gewenste constraints);
  **minimale backend** (datapijplijn + proxy, routering on-device); MVP = Planmodus
  voor alle vijf landen; distributie via **sideload** (geen Play Store); prijzen
  betrekken via een **reisgezelschap-model** (leeftijden als getal, kortingskaarten
  per reiziger).
- Drie parallelle onderzoeken verifieerden alle databronnen (`docs/databronnen.md`):
  statische GTFS-feeds (URLs, groottes, licenties), realtime/verrijking (per land),
  en prijs-API's. Hoofdconclusies: NL en CH zijn open-datarijk; DE is fragiel
  (30-dagen-horizon gratis feeds, geen landelijke realtime, samenstelling alleen
  onofficieel); FR-tarieven zijn officieel alleen als indicatie beschikbaar
  (live zit achter Datadome); **Eurostar/NS International is het grote gat**
  (B2B-only). Gebruikersvoorwaarden van alle portalen samengevat in `TODO.md`.
- **Fase 0.5 (vertragingskaart)** op verzoek toegevoegd: realtime kaart met
  kleurcodering per baanvak; de voedende aggregator is tevens de
  punctualiteitscollector (FR/BE hebben geen rit-niveau-archief; check bevestigde
  dat transport.data.gouv.fr de realtime-feed níet archiveert).

## 2. Fase 0 — spike (alle zes vragen beantwoord, `docs/SPIKE-RESULTATEN.md`)

- Dataset van vijf landen rail-only: **35 MB** (tar.zst); ETL < 4 min, piek 2,3 GB
  → past ruim in GitHub Actions (hostingbesluit bevestigd).
- Naïeve **RAPTOR in Python: 0–41 ms per query** (Amsterdam→Lyon) → on-device
  routering in Kotlin ruim haalbaar. Plausibiliteit dubbel bevestigd doordat de
  planner correct met zomerwerkzaamheden omging (ingekorte IC's naar Maastricht).
- **Eurostar zit in de NL-feed** (incl. Londen); geen verwachte internationale
  dienst ontbreekt volledig. CH-feed reikt verrassend diep in Frankrijk.
- Duplicaat-treindetectie werkt maar moet dienstdag-bewust worden (ETL-les);
  stationsclustering via UIC + naam/afstand, met bekende naamvariant-missers.

## 3. Fase 0.5 — aggregator + kaart

- **Aggregator** (Python, `pipeline/aggregator/`): pollt GTFS-RT per land, berekent
  **delta-vertraging per baanvak** (alleen expliciete stop-updates), archiveert
  observaties in SQLite (= punctualiteitscollector), publiceert elke minuut een
  compact snapshot. Landen zijn pluggable via `.env`.
- **Viewer** (`web/vertragingskaart/`, MapLibre): kleurcodering
  groen/geel(≤2 min)/oranje(≤10)/rood(>10) naar opgelopen vertraging,
  oorzaak-iconen uit service alerts, tooltips, dekkingspaneel per land.
- Live-verificaties tegen de werkelijkheid: de storing Utrecht–Geldermalsen
  kleurde correct; de omgeleide Amsterdam–Berlijn (via Hamburg, wegens Duitse
  werkzaamheden) bleek écht in de data te zitten.

## 4. Infrastructuur (alles free-tier)

- **GitHub** `wijnand-suijlen/reisplan`: code, dagelijkse **dataset-ETL-workflow**
  (03:30 UTC, dataset + metingen als artifacts, upload naar R2), **Pages-workflow**
  voor de viewer.
- **Cloudflare R2** als "brievenbus": aggregator uploadt snapshot (gzip) elke
  minuut; ETL en geometrie-artefacten ernaast; viewer leest publiek via de
  r2.dev-URL (CORS: alleen-GET).
- **Google Cloud e2-micro** (Oracle's aanmelding weigerde; GCP als alternatief):
  `deploy/setup-vm.sh` richt alles in (swap voor de 1 GB RAM, uv, systemd-services);
  wekelijkse dataverversing via `deploy/vernieuw.sh` (doet zelf `git pull`).

## 5. Kaart-iteraties (dag 2)

1. **Segmentverfijning**: expresse-sprongen via kortste-pad afgebeeld op de keten
   van fijnere baanvakken (4.516 ontleed); delta's naar rato van afstand verdeeld.
2. **Null-Island-fix**: buitenlandse planningsstubs op (0,0) gerepareerd via
   naam-matching.
3. **v2-geometrie** (`spike/s8`): OSM-spoorgraaf uit Geofabrik-extracten van zes
   landen (4,1 M knopen → 617k randen), stations gesnapt, **18.658 van 20.626
   baanvakken over het echte spoor gerouteerd** (A*, 47 s).
4. **Rand-gebaseerde aggregatie** (na een s9-inventaris van dubbeltekeningen):
   dissolve van de knooppaden naar **27k getekende randen** — elk stuk fysiek spoor
   is één lijn, gekleurd met het aggregaat van álle treinen die eroverheen rijden.
   Daarmee zijn alle drie de dubbeltekening-oorzaken per constructie verdwenen.

## Verrassingen die code-aanpassingen vergden

| Verrassing | Aanpassing |
|---|---|
| OVapi: treinen zitten in `trainUpdates.pb`, niet `tripUpdates.pb` | NL-bron-URL |
| BE: eigen key-header `bmc-partner-key`; levert alléén JSON met JS-Long-objecten | JSON-parser + Long-normalisatie |
| CH: protobuf-variant van GTFS-SA is corrupt; per API een aparte key; SA-feed is 18 MB | JSON-variant, aparte alerts-headers en -interval |
| Kapot `~/.aws/config` op de laptop brak boto3 | expliciete config, AWS-bestanden genegeerd |
| e2-micro (1 GB): OOM in de paren-query | `lead()`-window i.p.v. gecorreleerde subquery + DuckDB-geheugenlimieten |
| Browser-SSH van GCP verbreekt → setup gecrasht | nohup-werkwijze; verversing gedelegeerd aan script dat via git pull mee-updatet |
| Elke poll herhaalt dezelfde observaties (~75 M rijen/dag) | alleen-bij-wijziging-opslag |
| `.env.swp` (vim-swap) bleek gecommit | historie herschreven en gepurged vóór de push; tevens auteur gecorrigeerd naar persoonlijk account |

## Stand en openstaand

- **Draait**: aggregator (laptop én VM), dagelijkse ETL, R2-distributie, viewer.
- **Nog te doen door eigenaar**: Pages-source aanzetten (→ publieke kaart-URL);
  VM-update draaien en melden zodat de laptop-aggregator uit kan; registraties
  DB Marketplace + DELFI (voor Duitsland), NS-portaal + NDOV (fase 1/2).
- **Verbeterlijst kaart** (PLAN.md §6): route-highlight bij klik, blokkade-stippellijn,
  drukte-kleurmodus, incident-filter (CH-werkzaamhedenwolk), gastdata-nuance in het
  dekkingspaneel, venstersemantiek (voorspeld vs. gerealiseerd).
- **Volgende grote fase**: fase 1 — de Kotlin-app met eigen RAPTOR-engine.
